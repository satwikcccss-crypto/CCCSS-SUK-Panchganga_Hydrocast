    Security, Authentication & Rate Limiting Architecture¶

    HydroCast implements defense-in-depth API security engineered for critical flood forecasting infrastructure, featuring a two-tier API key hierarchy, administrative JWT authentication, bcrypt password hashing, SlowAPI rate limiting, and DoS connection throttling.

    1.1 Key Tiers and Access Scopes¶

    Key Class Configuration Variable Scope of Permissions Accepted by /api/v1/admin/*?
    Master API Key API_KEY Full public read access and administrative fallback YES
    Consumer Read-Only Keys HYDROCAST_READONLY_KEY
    HYDROSIM_API_KEY
    CONSUMER_API_KEYS    		 Read-only public endpoints (e.g. /api/v1/water-levels) NO (Strictly Forbidden)

    1.2 Constant-Time Timing-Attack Defense¶

    To prevent timing side-channel attacks from disclosing key lengths or secret prefixes, src/api/keys.py utilizes constant-time comparison via Python's hmac.compare_digest. All configured keys are evaluated in constant time without short-circuiting:

    def verify_consumer_key(supplied: str | None) -> bool:
    """True if supplied matches any consumer key. Always fail-closed."""
    if not supplied:
        return False
    matched = False
    for key in consumer_keys():
        matched |= hmac.compare_digest(supplied.encode("utf-8"), key.encode("utf-8"))
    return matched

    1.3 Zero-Downtime Consumer Key Rotation¶

    The CONSUMER_API_KEYS environment variable accepts a comma-separated list of active keys (key_v1,key_v2). This enables zero-downtime rotation for external consumers (such as HydroSim 2D or district authorities): 1. Append the new key to CONSUMER_API_KEYS. 2. Update the downstream consumer to use the new key. 3. Remove the retired key from CONSUMER_API_KEYS.

    1.4 Public Zero-Key Mode (Opt-In)¶

    REQUIRE_API_KEY defaults to true, so a missing configuration fails closed. Set it to false only when you intentionally want Open-Meteo-style unauthenticated public reads:

    REQUIRE_API_KEY=false
RATE_LIMIT_PUBLIC=60/minute
RATE_LIMIT_BURST=10/second
PUBLIC_CACHE_MAX_AGE=300

    In this mode only GET /api/v1/* reads bypass the key check. /api/v1/admin/* and all write/trigger paths remain protected by JWT or the master API_KEY; verify_admin_auth does not consult REQUIRE_API_KEY. The keyed mode remains available (X-API-Key or ?key=) for district deployments that require gating.

    Successful public GETs receive Cache-Control: public, max-age=300 (PUBLIC_CACHE_MAX_AGE). Health probes, admin routes, keyed responses, error responses, and writes stay no-store, so a shared CDN can absorb forecast traffic without caching credentials or failures.

    2. Administrative Authentication & JWT Tokens (src/api/security.py)¶

    Administrative operations (POST /api/v1/admin/*, parameter recalibration, run archival) require authenticated credentials.

    2.1 Cryptographic Token Standards¶

    • Algorithm: Symmetric HMAC-SHA256 (HS256).
    • Algorithm Confinement: Locked strictly to _ALLOWED_JWT_ALGORITHMS = {"HS256", "HS384", "HS512"}. Insecure algorithms like "none" or asymmetric confusion variants are rejected at startup.
    • Expiration: JWT_EXPIRATION_MINUTES = 1440 (24-hour lifetime).
    • Token Claims: Payload contains {sub: username, role: "admin", iat: timestamp, exp: timestamp} with issuer iss: "hydrocast-api".

    2.2 Password Hashing (Bcrypt) & Fail-Closed Guard¶

    • Storage: Administrator passwords are never stored in plaintext; passwords are hashed using bcrypt with per-hash salt (hash_password, verify_password).
    • Fail-Closed Guarantee: 
      def verify_admin_credentials(username: str, password: str) -> bool:
    if not ADMIN_PASSWORD or not ADMIN_USERNAME:
        return False
    valid_user = hmac.compare_digest(username.strip().encode("utf-8"), ADMIN_USERNAME.strip().encode("utf-8"))
    valid_pass = hmac.compare_digest(password.encode("utf-8"), ADMIN_PASSWORD.encode("utf-8"))
    return valid_user and valid_pass
      If ADMIN_PASSWORD is unconfigured, login immediately fails closed rather than matching an empty string.

    3. SlowAPI Request Rate Limiting (src/api/limits.py)¶

    To prevent API scraping, denial of service, and brute-force password guessing, HydroCast integrates SlowAPI rate limiting:

    Target Endpoint Surface Rate Limit Budget Target Protection
    Public Read Endpoints (/api/v1/*) 60 / minute + optional 10 / second burst Prevents bandwidth saturation and scraping
    Admin Login Endpoint (/api/v1/admin/auth/token) 5 / minute Mitigates credential brute-forcing attacks

    Rate limits key off the client remote IP address (get_remote_address). Rate-limit headers (X-RateLimit-Limit, X-RateLimit-Remaining, X-RateLimit-Reset) are returned with every response. RATE_LIMIT_BURST is optional; when set, SlowAPI enforces both windows.

    4. Hardening & DoS Mitigations (src/api/main.py)¶

    4.1 WebSocket Connection Throttling¶

    To protect server memory and file descriptors from connection-exhaustion attacks, the live WebSocket manager enforces a hard connection cap: 

    class WSManager:
    MAX_CONNECTIONS = int(os.getenv("MAX_WS_CONNECTIONS", "200"))
    When concurrent connections reach 200, additional connections are rejected with WebSocket close code 1013 (Try Again Later).

    4.2 Request Body Size Guard¶

    A custom Starlette middleware intercepts all incoming HTTP requests, rejecting payloads exceeding 1 MB (MAX_REQUEST_BYTES, default 1_000_000) with HTTP 413 (Payload Too Large).

    4.3 Path Traversal Prevention¶

    Historical run queries enforce strict regular expression validation on run_id: 

    if not re.match(r"^[a-zA-Z0-9_-]+$", run_id):
    raise HTTPException(status_code=400, detail="Invalid run_id format")
    This guarantees that queries containing ../ or special characters cannot traverse local storage directories.

    def verify_admin_credentials(username: str, password: str) -> bool:
    """Verify administrator login credentials with constant-time comparison.

    Fails closed: if ``ADMIN_PASSWORD`` (or ``ADMIN_USERNAME``) is not configured,
    no login can succeed. Without this guard an unset password would compare
    equal to an empty submitted password and mint an admin token.
    """
    if not ADMIN_PASSWORD or not ADMIN_USERNAME:
        return False
    valid_user = hmac.compare_digest(
        username.strip().encode("utf-8"), ADMIN_USERNAME.strip().encode("utf-8")
    )
    # Password is compared exactly (no trimming) so whitespace is significant.
    valid_pass = hmac.compare_digest(
        password.encode("utf-8"), ADMIN_PASSWORD.encode("utf-8")
    )
    return valid_user and valid_pass

    async def verify_admin_credentials_db(
    username: str,
    password: str,
    db_pool: Any = None,
) -> tuple[bool, str]:
    """Verify administrator credentials against Postgres admin_users table with env fallback.

    Returns:
        (is_authenticated, role) where role is 'govt', 'dev', or 'admin'.
    """
    if db_pool is not None:
        try:
            async with db_pool.acquire() as conn:
                row = await conn.fetchrow(
                    "SELECT password_hash, role FROM admin_users WHERE username = $1",
                    username.strip(),
                )
                if row:
                    pwd_hash = row["password_hash"]
                    role = row.get("role", "dev")
                    if verify_password(password, pwd_hash):
                        try:
                            await conn.execute(
                                "UPDATE admin_users SET last_login = NOW() WHERE username = $1",
                                username.strip(),
                            )
                            await conn.execute(
                                """INSERT INTO admin_login_log (username, role, success)
                                   VALUES ($1, $2, TRUE)""",
                                username.strip(), role
                            )
                        except Exception:
                            pass
                        return True, role
                    else:
                        try:
                            await conn.execute(
                                """INSERT INTO admin_login_log (username, role, success)
                                   VALUES ($1, $2, FALSE)""",
                                username.strip(), role
                            )
                        except Exception:
                            pass
        except Exception as e:
            _sec_log.warning("Database admin authentication check failed or table missing: %s", e)

    # Fallback to environment credentials (emergency break-glass / zero-db bootstrap)
    if verify_admin_credentials(username, password):
        return True, "admin"

    return False, ""

    def create_access_token(
    subject: str,
    role: str = "admin",
    expires_delta: Optional[timedelta] = None,
) -> str:
    """Generate signed JWT access token."""
    expire = datetime.now(timezone.utc) + (
        expires_delta if expires_delta else timedelta(minutes=JWT_EXPIRATION_MINUTES)
    )
    payload = {
        "sub": subject,
        "role": role,
        "exp": expire,
        "iat": datetime.now(timezone.utc),
        "iss": "hydrocast-api",
    }
    return jwt.encode(payload, JWT_SECRET, algorithm=JWT_ALGORITHM)

    def decode_access_token(token: str) -> Dict[str, Any]:
    """Decode and validate a JWT access token."""
    # Attempt decoding with ADMIN_JWT_SECRET, then fall back to JWT_SECRET
    secrets_to_try = [s for s in (ADMIN_JWT_SECRET, JWT_SECRET) if s]
    last_err = None
    for secret in dict.fromkeys(secrets_to_try):
        try:
            payload = jwt.decode(
                token,
                secret,
                algorithms=[JWT_ALGORITHM],
                issuer="hydrocast-api",
            )
            return payload
        except jwt.ExpiredSignatureError:
            raise HTTPException(
                status_code=status.HTTP_401_UNAUTHORIZED,
                detail="JWT token has expired",
                headers={"WWW-Authenticate": "Bearer"},
            )
        except jwt.PyJWTError as err:
            last_err = err

    raise HTTPException(
        status_code=status.HTTP_401_UNAUTHORIZED,
        detail="Invalid or malformed JWT token",
        headers={"WWW-Authenticate": "Bearer"},
    )

    async def verify_admin_auth(
    credentials: Optional[HTTPAuthorizationCredentials] = Security(security_bearer),
    x_api_key: Optional[str] = Header(None, alias="X-API-Key"),
) -> Dict[str, Any]:
    """
    Unified security dependency for administrative endpoints.
    Accepts EITHER:
      1. Valid JWT in Authorization: Bearer <token>
      2. Valid master key in X-API-Key: <key>
    """
    # 1. Check Bearer token
    if credentials and credentials.credentials:
        token = credentials.credentials
        return decode_access_token(token)

    # 2. Check X-API-Key fallback. Fail closed when no key is configured so an
    #    empty configured key can never authorise an empty/extra header.
    if API_KEY and x_api_key and hmac.compare_digest(x_api_key.encode("utf-8"), API_KEY.encode("utf-8")):
        return {"sub": "system_api_key", "role": "admin"}

    raise HTTPException(
        status_code=status.HTTP_401_UNAUTHORIZED,
        detail="Unauthorized. Provide a valid Bearer JWT token or X-API-Key header.",
        headers={"WWW-Authenticate": "Bearer"},
    )

    src/api/keys.py¶

    keys ¶

    src/api/keys.py¶

    Scoped API keys for read-only external consumers.

    HydroCast has two key classes:

    • Master key (API_KEY) — full public + admin fallback (newsroom / ops).
    • Consumer keys — read-only public reads only. They are never accepted by the admin router. This lets an external model (Hydrosim / HEC-RAS) pull water levels without holding the master credential.

    HYDROCAST_READONLY_KEY is the named read-only key for an external flood model (Hydrosim / HEC-RAS). The older name HYDROSIM_API_KEY is still accepted as an alias, so existing setups do not break. CONSUMER_API_KEYS is a comma-separated list for zero-downtime rotation: add the new key, deploy the consumer with it, then remove the old one.

    Every comparison is constant-time, and all configured keys are compared even after a match so timing does not disclose how many keys exist.

    def verify_public_key(supplied: str | None, master_key: str) -> bool:
    """True for the master key or any consumer key (public reads only)."""
    if not supplied:
        return False
    matched = bool(master_key) and hmac.compare_digest(
        supplied.encode("utf-8"), master_key.encode("utf-8")
