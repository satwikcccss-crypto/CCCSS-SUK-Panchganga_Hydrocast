HydroCast — Deployment View: Linux Docker vs Windows Server

Multi-Container Orchestration (Docker Compose v2) vs Dedicated Physical Tablespace on E:\ (Windows Server 2022)

DIAGRAM: 06-DEPLOYMENT-DOCKER-OS
AUDIT STANDARD: GOVERNMENT-RECORD / STATIC ARCHITECTURE

ENVIRONMENT A: LINUX DOCKER COMPOSE

docker-compose.yml · Dockerfile · Network: hydrocast-net (bridge)

1. Database Service (hydrocast-db) Port 5432:5432
Image: postgis/postgis:15-3.4 · Container: hydrocast-db
Volumes: postgres_data:/var/lib/postgresql/data
Init SQL: ./database/supabase_schema.sql:ro
Healthcheck: pg_isready -U hms_app -d rainfall_runoff (interval 10s)
Security: no-new-privileges: true
2. Backend Runtime (hydrocast-backend) Port 8000:8000
Multi-Stage Dockerfile (target: runner) · Image: hydrocast-backend:2.0.0
Runtime: Python 3.12 + OpenJDK 17 + GDAL 3.2 + eccodes + pydsstools
User: hydrocast:1000 (Non-root) · Init: /usr/bin/tini --
Command: uvicorn src.api.main:app --workers 2 --timeout-graceful 30s
Named Volumes: hydrocast_runs, hydrocast_telemetry, hydrocast_forecast, hydrocast_raw, hydrocast_archives, hydrocast_logs
Healthcheck: curl -fsS http://localhost:8000/api/v1/health (interval 15s)
Security: cap_drop: ALL · stop_grace_period: 45s
3. Frontend Dashboard (hydrocast-frontend) Port 3000:3000
Context: ./frontend · Next.js 14 Production Container
Environment: NODE_ENV=production
API URL: http://localhost:8000 · WS URL: ws://localhost:8000/ws/live
Healthcheck: wget --spider http://localhost:3000/ (interval 20s)
Security: cap_drop: ALL · no-new-privileges: true
4. Documentation Server (hydrocast-docs) Port 8001:8001
Profile: docs · MkDocs Material Engine (--strict validated)
Volumes (Read-Only Live Reload): ./docs:/app/docs:ro, ./src:/app/src:ro, ./mkdocs.yml:ro
Command: mkdocs serve --dev-addr 0.0.0.0:8001
5. Development & Testing (hydrocast-dev) Ports 8000, 8888
Profile: dev · Runtime + Pytest + Ruff + JupyterLab
Volumes: ./src:/app/src:ro, ./tests:/app/tests:ro, ./notebooks:/app/notebooks:ro
Token: JUPYTER_TOKEN=hydrocast-dev · Interactive shell: bash

ENVIRONMENT B: WINDOWS SERVER 2022 DEDICATED

windows/install_postgres.ps1 · windows/storage_setup.sql · 3512GB Tablespace

1. Physical Drive Partitioning & Tablespace Capacity: 3512 GB
Dual-Drive Architecture (OS / Fast I/O vs High-Capacity Storage)
System Drive C:\ or D:\: OS, binaries, and default pg_default
Data Drive E:\ (3512 GB): Dedicated PostgreSQL Tablespace `hydrocast_data`
Location: E:\pgtablespace\hydrocast
WAL Logs Drive: E:\pgwal · System Logs: E:\pglogs
Local Raw GRIB2/NetCDF Archive: E:\hydrocast\data\raw
2. Native PostgreSQL 16 Windows Service Port 5432
Service: postgresql-x64-16 · EnterpriseDB Native Windows x64
Extensions: timescaledb 2.15.3, postgis, pg_cron, pg_stat_statements
RAM-Tuned Configuration (Auto-detected in install_postgres.ps1):
- shared_buffers = 25% RAM · effective_cache_size = 75% RAM
- max_wal_size = 8GB · checkpoint_completion_target = 0.9
Service Account: NT AUTHORITY\NetworkService with FullControl ACLs
3. TimescaleDB Compression & Retention Engine Compression: 5–10x
Automated Storage Management on Drive E:\ (storage_setup.sql)
ecmwf_forecast: compress after 3 days · drop after 90 days
subbasin_rainfall_ts: compress after 7 days · retention: indefinite
rainfall_data: compress after 7 days · retention: indefinite
bridge_stage_forecast: compress after 7 days · drop after 365 days
system_logs: compress after 3 days · drop after 180 days
pg_cron maintenance: weekly-vacuum (Sunday 03:00), daily-compress (02:30)
4. Native USACE HEC-HMS 4.13 Batch Engine Native EXE
Installed Path: C:\Program Files\HEC\HEC-HMS\4.13\HEC-HMS.exe
Headless Mode: "HEC-HMS.exe" -s compute.jy
Automation Jython Script: compute.jy targeting 'Run 1'
Project File: data/hms/HMS_Automation_RJKT/HMS_Automation_RJKT.hms
Dynamic Window Patching: Control_1.control patched for 90-hr forecast horizon
5. Windows Task Scheduler (Automation Runner) Cron Equivalent
Scheduled Task: "HydroCast_Sync_Cycle"
Trigger: Runs every 6 hours (02:30, 08:30, 14:30, 20:30 UTC)
Action: powershell -ExecutionPolicy Bypass -Command "python -m src.orchestrator"
Logging: logs/pipeline.log and database table pipeline_step_log
